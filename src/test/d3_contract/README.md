# d3 contract test

`test_d3_contract` checks FastFlowLM's port of the d3 (Decision 3.0) System One contract
(`src/common/decision`) against the upstream package it reproduces, `vllm-sr/d3-lite` at `v3.1.3`
(`d3_format.py`, `d3_runtime.py`, `d3_server.py`). No NPU and no model weights are involved.

For every fixture request it requires:

- the rendered prompt of every question, byte for byte;
- the same request-level refusal (the 422 `detail` text d3_server sends) or the same `invalid_questions`;
- from the same fp32 option probabilities, the same answer objects: keys, key order, types, and every number
  bit-identical (Python 3.12's compensated `sum()` included).

With `-DFLM_D3_TEST_TOKENIZER=ON` and the model package as the second argument, it also checks every token id and
that the tokenizer yields the package's 255 answer codes.

```bash
cmake -S src/test/d3_contract -B build-d3-contract && cmake --build build-d3-contract
ctest --test-dir build-d3-contract --output-on-failure
```

## Fixtures

`fixtures/` is generated by `gen_fixtures.py` with the upstream package's own Python runtime:

- `goldens.jsonl`: 308 hand-built golden requests (all question types, 1-255 options, the 26/27 two-letter code
  boundary, JSON states and descriptions, unicode and control characters, special-token text, invalid questions)
  with their prompts, token ids, BF16 probabilities and in-process responses;
- `fuzz.jsonl`: 1,000 fixed-seed random request *bodies* (raw JSON text, so number spellings and duplicate keys
  reach the parser): every JSON value type, floats around Python's repr switch points, integers beyond 64 bits,
  falsy values, invalid shapes, unknown fields, malformed JSON -- with what upstream answers for each;
- `images.jsonl`: 57 image requests as the server reads them (base64 data URLs of small synthetic PNG/JPEG/WebP
  files at every resize regime -- upscaled, exact 1.6 MP, shrunk, portrait, aspect 200, half-even rounding -- plus
  malformed inputs): upstream's 422 texts, prompts, image grids, input token ids with each `<|image_pad|>` expanded,
  and the `max_length_exceeded` texts at a 2,000-token limit. Refusals that come from decoding pixels (integrity)
  are marked `stage: "decode"`: the contract library reads headers only, the server decodes. PIL's
  "cannot identify image file" text carries an object address, which the test drops;
- `decision_config.json`: the package's answer codes.

Regenerating them is a reviewed change: the fixtures are the definition of "identical to upstream".

## prefix_bidir state block (d3:turbo)

`fixtures/state_split.jsonl` (`gen_state_split.py`, upstream `d3_format.encode_split` with the tokenizer's offset mapping)
holds 457 rendered prompts (the committed subset: all image prompts and every 4th other prompt of the generator's ~1,480) (the golden states, edge states ending in punctuation, whitespace, newlines, unicode,
non-NFC text and special-token text, random mixes, and image prompts) with their token ids (crc) and the state block
length S. FastFlowLM's tokenizer API has no offsets, so `state_block_length` derives S from each token's byte length;
`test_d3_state_split <fixtures>/state_split.jsonl <D3-Turbo-NPU2 dir> <fixtures>/images.jsonl` (built with
`-DFLM_D3_TEST_TOKENIZER=ON`) requires the same S for every prompt. Three prompts with combining marks (Thai,
Devanagari) are tokenized differently by transformers' `Qwen2Tokenizer` (its own pre-tokenizer regex) and by
`tokenizer.json`; for those the expected S comes from `tokenizer.json`'s own offsets.
